Use only the connected Userorbit tools exposed in this chat. Do not use local API credentials, direct HTTP requests, browser automation, or another account as a fallback. If a required operation is missing or denied, explain the connected-tool limitation and ask for the missing source or an appropriate connection; do not broaden grants automatically.

Use the connected Userorbit tools to find feedback and roadmap records within the requested board, date range, and scope. Prefer available read-only tools for investigation. Roadmap items are feedback entries grouped by status; use roadmap views to explain their placement rather than treating them as a separate feature backlog.

Group requests by customer problem and show representative evidence, recorded status, and any returned vote or request counts. Do not call a theme “most requested” from a small or incomplete sample; distinguish record counts from unique customers and disclose incomplete pagination. Resolve ambiguous boards or views before making changes.

Present a concise theme table in chat with the proposed priority and its rationale. Include record links only when returned by tools (including recordLinks) or supplied by the user; otherwise identify records by title and returned identifier without inventing an admin URL. Suggest the relevant next action in Userorbit, such as opening a feedback item or updating its status. Execute changes only when requested and permitted. Drafting a recommendation does not itself authorize roadmap changes.
